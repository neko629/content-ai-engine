# 产品需求文档 PRD 生成引擎

本 Skill 负责将用户输入的各种形式（需求描述、原型说明、网站链接、业务想法等）转化为结构完整、可执行交付的产品需求文档（PRD）。

> **核心原则**
> 1. PRD 回答"做什么、为谁做、为什么"，不替代技术设计文档去回答"怎么实现"。数据库、接口、技术栈等内容默认放入可选附录，且**不凭空编造**。
> 2. **先确认，再生成**：核心要素缺失时先向用户提问，不要用假设糊上去。
> 3. **深度随输入成熟度变化**：模糊想法只写到功能与流程层，不强行补出精确但虚假的技术细节。
> 4. 生成后必须做一致性自检，不得残留占位符 `____`。

---

## 输入预处理（在一切之前：先把内容拿到手）

PRD 的所有判断都基于"已读到的真实内容"。开始前先按输入形态获取内容，**不得在内容缺失时凭空编造**。

| 输入形态 | 执行动作 | 使用工具 |
|---------|----------|----------|
| 纯文字需求 | 直接进入下一步 | 无 |
| 网站/页面链接 | 先抓取页面文本；静态页用 web 抓取，若返回空壳/加载占位/需登录（JS 客户端渲染），改用浏览器渲染后读取 | WebFetch → 不行则 Chrome 工具 |
| 上传文件（pdf/docx/原型/截图） | 先读取解析为文本再进入流程；截图可直接看图 | Read；必要时配合 pdf / docx skill |
| 多个素材混合 | 逐个读取后汇总，再统一解析 | 上述组合 |

**失败兜底**：抓取或读取失败时，不要假造页面功能或文档内容。如实告知用户哪一项没拿到，请其补充链接权限、改贴文本或重新上传，然后回到下方信息门禁的"先提问"逻辑。

## 〇、生成前置：信息门禁（必须最先执行）

### 0.1 完整性评估

逐项评估输入覆盖度：

- 【 】核心业务目标明确
- 【 】目标用户群体清晰
- 【 】核心问题/痛点清晰
- 【 】主要功能需求有大致方向
- 【 】主要用户流程有大方向
- 【 】成功衡量标准有倾向（或可推断）

### 0.2 判定规则（关键）

| 情况 | 处理方式 |
|------|----------|
| **核心三要素**（业务目标 / 目标用户 / 核心问题）任一缺失 | **停止生成，先向用户提问**。一次最多问 3 个最关键问题，不得用【假设】绕过 |
| 仅次要信息缺失（流程细节、字段、边界等） | 可标【假设】继续，并在第十章统一汇总 |
| 输入已较完整 | 直接进入解析与生成 |

### 0.3 输出形式确认

开始前明确（缺失则简短询问或合理默认）：读者对象（业务/开发/设计/高层）、期望篇幅与详略、是否需要技术附录。

## 一、输入识别与深度分级

### 1.1 输入类型判断

| 输入类型 | 处理策略 | 输出侧重 |
|---------|----------|----------|
| 模糊业务想法 | 补全产品逻辑 + 提问澄清核心 | 功能与流程层，假设全标记 |
| 需求描述（较完整） | 结构化拆解，直接生成 | 完整 PRD 主体 |
| 网站/页面链接 | 结构拆解 + 功能还原 | 页面 + 功能清单 |
| 原型文件描述 | 页面 + 交互解析 | 交互说明 + 状态 |
| 已有文档/素材 | 提取核心信息重组 | 重构后的完整 PRD |

### 1.2 深度分级（避免"精确的错误"）

输出深度必须匹配输入成熟度：

| 输入成熟度 | 写到哪一层 | 不要做什么 |
|-----------|-----------|-----------|
| 早期想法 | 目标、用户、场景、核心功能、主流程 | 不编数据库表、不编接口、不锁技术栈 |
| 功能明确 | 上述 + 功能详设、业务规则、范围与指标 | 技术细节仍放附录且仅在有依据时写 |
| 含技术决策 | 上述 + 技术参考附录 | —— |

## 九、生成后一致性自检（必须执行）

逐条核对，未通过则回修对应章节：

- 【 】第四章每个功能模块都能追溯到第三章的某条用户流程（无悬空功能）
- 【 】第三章每条主流程涉及的功能都已在第四/五章覆盖（无遗漏入口）
- 【 】第五章功能的输入/输出字段彼此自洽，能支撑交互逻辑
- 【 】第六章非目标与第四章功能范围不矛盾
- 【 】第七章指标可衡量、与第二章业务价值对应
- 【 】**全文不残留任何 `____` 占位符**；确实未知的，改为【假设：…】或【待确认：…】，并在第十章登记

## 十一、成果交付

PRD 主体完成后，按 0.3 确认的输出形式交付：

- **默认**：在对话内直接输出完整 PRD。
- **用户要文件时**：正式 PRD 用 docx skill 生成 `.docx`；轻量留存写 `.md` 文件。生成后将文件呈现给用户下载，不要只贴正文。
- **形式未确认**：在第〇章的 0.3 阶段就问清"是否需要文件、什么格式"，避免做完再返工。
