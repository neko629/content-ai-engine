# 模式 A · 全量速测

## 适用场景

- 项目上线前快速过一遍质量
- 时间盒有限，需要"广度优先"
- 用户没有指定具体测试方向

## 流程

```
1. 输入盘点（5 分钟级）
   └─ 罗列已有原型/UI/接口文档/代码/环境，标出缺失项
2. 测试范围圈定
   └─ 列出涉及的页面/模块/接口
3. 21 维度快速过一遍
   └─ 每个维度只列 3–8 条最关键的测试点
4. 主流程冒烟测试用例（5–10 条）
5. 工具实测主流程（如环境可用）
   └─ Bash + Chrome 跑一遍 happy path
6. 输出"全量速测报告"
```

## 输入要求（按优先级）

- 必需：测试范围（哪些页面/接口）、主流程描述
- 推荐：原型 / UI 稿 / 接口文档之一
- 加分：代码仓库、运行环境

## 产出（必须包含）

1. 测试范围
2. 21 维度测试点速览表（每维度 3–8 条）
3. 主流程冒烟用例（5–10 条）
4. 已知/推断高风险问题清单
5. 后续深测建议（指明应进入 deep-dive 模式的维度）

## 退出条件

- 21 维度全覆盖（不适用维度需注明原因）
- 主流程冒烟用例可被客观判定
- 至少识别 3 个高风险点（无则说明为何无）

## 工具调用约束

时间紧，工具调用以"快速验证主流程"为主：
- 至少跑一次 `npm run build` 或对应构建命令（如有代码）
- 至少跑一次主流程页面 Chrome 实测（如有 URL）
- 不深入每个维度的工具实测

## 协作模式

完成后主动建议：
> "已完成全量速测，识别出以下维度为高风险：[X]、[Y]、[Z]。建议下一步对其中任一项进入「分项深测」模式，是否继续？"
