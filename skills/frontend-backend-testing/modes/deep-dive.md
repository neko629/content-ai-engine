# 模式 B · 分项深测（默认模式）

## 适用场景

- 用户明确要求"逐项测试 UI 布局 / 功能逻辑 / 接口 / 代码"
- 单一维度深入测试
- 全量速测后的二次深入
- 没指定模式时的默认行为

## 流程

```
1. 用户/Claude 选定一个维度（或维度组）
   └─ 例：02-ui-layout、03-api-integration、18-static-analysis
2. Read 对应 dimensions/<NN-name>.md，获取该维度的：
   ├─ Checklist（要看什么）
   ├─ 测试方法（怎么测）
   ├─ 常见 Bug 模式（避免漏测）
   └─ 通过判定（合格标准）
3. 测试输入分析（针对该维度）
   ├─ UI 维度：提取设计 token + 组件状态矩阵 + 断点表
   ├─ 接口维度：提取契约表 + 错误码全集
   ├─ 状态维度：提取状态机表
   ├─ 代码维度：提取路由/组件/调用关系
   └─ ……
4. 测试设计（调用 methods/）
   ├─ 输入校验类 → boundary-value + equivalence-partitioning
   ├─ 状态流转类 → state-transition
   ├─ 多变量组合类 → decision-table + orthogonal-array
   └─ 端到端流程类 → scenario-based
5. 工具实测（按 dimensions/ 中"测试方法"指引）
   └─ 必须实测，不能纯推理
6. 输出"分项深测报告"
```

## 输入要求

- 必需：测试目标维度（或让 Claude 推断）
- 必需：该维度相关原料（UI 稿/接口文档/代码/原型）
- 推荐：运行环境或代码仓库（便于实测）

## 产出（必须包含）

1. 维度名称 + 测试目标
2. 测试输入分析（结构化提取结果）
3. 测试设计（用了哪些方法、生成的测试矩阵）
4. 测试用例表（按方法穷举出的全部用例）
5. 工具实测过程与结果（命令 + 输出摘录）
6. 问题清单（含严重度、复现步骤、修改建议）
7. 该维度回归建议
8. 与其他维度的关联点（提示下一步）

## 深度要求

分项深测必须达到以下深度，否则不算"深测"：

- 测试用例数：单维度 ≥ 15 条（简单页面除外）
- 至少使用 1 种 methods/ 测试设计方法并显式标注
- 至少有 1 次工具实测（除非环境完全不可达）
- Bug 模式库（checklists/）必须全部走查一遍

## 退出条件

- 该维度 Checklist 100% 覆盖（或注明不适用）
- 该维度 Bug 模式库已对照走查
- 至少 1 次实测
- 通过判定标准已在用例预期结果中体现

## 协作模式

完成后主动建议：
> "已完成「[维度名]」分项深测，发现 N 个问题。是否继续深测下一项？建议优先：[X]、[Y]（理由：……）"
