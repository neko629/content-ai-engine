# 模式 C · 增量回归测试

## 适用场景

- Bug 修复后验证
- 代码 diff 后判定影响面
- 迭代结束的回归测试
- 上线前的"最后一公里"复测

## 流程

```
1. 锚定变更范围
   ├─ 从 Bug 单/PR/Commit 提取改动文件清单
   ├─ Bash 跑 `git diff --name-only base...HEAD` 获取改动文件
   └─ Grep/Glob 反向找：改动文件被谁引用、关联哪些路由/接口
2. 影响面分析（受影响功能 = 改动文件 × 引用关系）
3. 测试范围 = 直接改动点 + 影响面 + 主流程冒烟
4. 测试用例集 = 失败 Bug 的复现用例 + 影响面用例 + 冒烟用例
5. 实测执行
6. 输出"回归测试报告"
```

## 输入要求

- 必需：变更说明（Bug 单 / PR 链接 / Commit hash / 改动列表）
- 必需：可访问的代码仓库
- 推荐：原 Bug 复现步骤、运行环境

## 影响面分析方法

按以下顺序排查，避免漏测：

1. **直接影响**：改动的代码本身（函数/组件/接口）
2. **调用方影响**：用 Grep 找改动符号的引用方
3. **数据影响**：改动是否涉及数据库表/字段/接口契约
4. **共享依赖影响**：改动是否在公共组件/工具/常量中
5. **配置影响**：是否动了配置文件、环境变量、构建脚本

## 产出（必须包含）

1. 变更摘要（改了什么、为什么改）
2. 改动文件清单（含 `git diff --stat`）
3. 影响面分析（受影响的页面/接口/功能列表）
4. 回归用例集
   - 原 Bug 复现用例（验证修复）
   - 影响面用例（验证未引入新问题）
   - 主流程冒烟用例（验证未破坏现有功能）
5. 实测结果
6. 新发现问题清单
7. 是否可上线/合入的明确结论（PASS / FAIL / 有条件 PASS）

## 工具调用约束

回归测试必须执行：

- `git diff --stat base...HEAD`（看改动范围）
- `git diff base...HEAD -- '*.test.*' '*.spec.*'`（看测试是否同步更新）
- `npm run lint && npm run test && npm run build`（基础三连）
- 原 Bug 复现路径的 Chrome 实测

## 退出条件

- 原 Bug 已验证修复（必须有"再次复现失败"的证据）
- 影响面内所有用例 PASS
- 主流程冒烟 PASS
- lint / test / build 三连 PASS
- 给出明确的 GO / NO-GO 结论
