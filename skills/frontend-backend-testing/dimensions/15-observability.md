# 维度 15 · 日志与可观测性测试

> 检查关键操作、接口异常、数据变更是否有日志记录，是否便于问题排查。

## Checklist

- 关键业务操作有审计日志（谁、何时、做了什么、对什么）
- 接口异常有错误日志（含 request id / trace id / 入参）
- 前端有埋点（关键操作 / 错误 / 性能）
- 日志含可追踪 ID（trace_id / request_id 贯穿前后端）
- 日志级别合理（DEBUG / INFO / WARN / ERROR）
- 日志不含敏感信息（密码、Token、身份证）
- 日志格式结构化（便于检索）
- 监控告警阈值合理（错误率、响应时间、CPU、内存）
- 健康检查接口可用
- 错误聚合工具接入（Sentry / Bugsnag）

## 测试方法

1. 触发各类操作 → 查日志（Bash tail / 日志平台）看是否记录
2. 模拟接口异常 → 看错误日志是否含 trace_id
3. 前端报错 → 看是否上报到错误平台
4. Grep 日志看是否含敏感字段

## 常见 Bug 模式

- 关键操作无审计日志（事后查不到谁动的）
- 异常被 catch 后 swallow（无日志无上报）
- trace_id 只在后端，前后端断链
- 日志含明文密码 / Token
- 日志级别一律 INFO，错误淹没
- 健康检查只检 HTTP 200，不检 DB 连接
- 监控阈值过高，告警来时已经雪崩

## 通过判定

- 关键操作 100% 有审计日志
- trace_id 贯穿前后端
- 异常路径日志完整
- 无敏感信息泄露到日志
