# 维度 20 · 代码可维护性（v2 新增）

> 命名、重复、模块边界、注释、副作用控制。

## Checklist

### 命名
- 变量 / 函数 / 文件 / 组件命名能直接表达意图
- 缩写不滥用（除非公认：URL / API / DB）
- 同概念同命名（user vs account vs member 不混用）
- Boolean 命名带 is/has/can 前缀

### 模块边界
- 单一职责（一个模块/函数做一件事）
- 接口清晰（参数少、显式、有类型）
- 副作用集中（纯函数 vs 副作用函数分层）
- UI / 状态 / 业务 / 数据 分层清晰

### 复用与重复
- 重复代码抽公共函数 / 组件
- 配置 / 常量集中管理（无散落魔法数）
- 工具函数库可复用

### 注释与文档
- 复杂逻辑有注释解释"为什么"（不是"是什么"）
- 公共 API 有 JSDoc / 类型注释
- README 含启动 / 构建 / 测试说明

### 错误处理
- 关键路径有 try/catch
- 异常分类（业务异常 vs 系统异常）
- 不 swallow 异常

## 测试方法

1. Grep 找魔法数字 / 硬编码字符串
2. 跑 jscpd / sonar 看重复
3. Read 关键文件做人工 review（看可读性）
4. Grep 找 `catch (e) {}` 空 catch

## 常见 Bug 模式

- 一个文件 2000 行什么都做
- `data1` / `data2` / `tmp` 命名
- 同概念三个名字混用
- 重复代码 10 处复制粘贴
- 注释只写"是什么"不写"为什么"
- 空 catch 吞异常
- 副作用散落各处（UI 直接改 DB）

## 通过判定

- 命名一致，无明显反模式
- 重复代码率符合基线
- 关键模块有注释和 README
- 异常处理策略明确
- 模块边界清晰
