# 维度 03 · 前后端接口联调测试

> 检查接口是否能正常调用，请求参数、返回数据、状态码是否正确。

## Checklist（要看什么）

### 契约一致性
- URL 路径与文档一致（含版本号）
- HTTP 方法一致（GET/POST/PUT/PATCH/DELETE）
- 请求 headers：Content-Type / Authorization / 自定义 header
- 请求体：字段名、类型、必填、默认值、嵌套层级
- 响应体：字段名、类型、嵌套结构、空值表示
- 状态码全集：2xx / 4xx / 5xx 全覆盖

### 业务规则
- 成功路径返回的数据是否满足业务字段需求
- 接口幂等性（POST 重复、PUT 重复结果一致）
- 排序、分页、过滤参数是否生效
- 字段含义是否与原型/UI 字段对得上（没有 mismatched 命名）

### 异常路径
- 必填字段缺失 → 400 + 错误结构
- 字段类型错误 → 400
- 越界值 → 400 / 业务错误码
- 鉴权失败 → 401
- 越权访问 → 403
- 资源不存在 → 404
- 业务冲突（如重复创建）→ 409 / 业务错误码
- 限流 → 429
- 服务端异常 → 500
- 网关超时 → 504

### 性能与可靠
- 接口响应时间（P50 / P95 / P99）
- 大数据量返回是否分页/分块
- 并发调用是否数据一致
- 超时与重试策略
- 跨域 CORS 配置

### 数据安全
- 敏感字段是否返回明文（手机号/身份证/密码）
- 返回字段是否过度暴露内部信息（DB 主键 → 应使用业务 ID）
- 是否使用 HTTPS
- Token 是否安全传输

## 测试方法

1. **契约表生成**：
   ```
   | 字段名 | 文档定义 | 实际请求 | 实际响应 | 一致性 |
   ```
2. **Bash 跑 curl 实测**：
   ```bash
   curl -i -X POST 'https://api.example.com/v1/users' \
     -H 'Content-Type: application/json' \
     -H 'Authorization: Bearer xxx' \
     -d '{"name":"test","age":18}'
   ```
3. **状态码全集探测**：构造各种错误输入，验证返回的状态码与文档一致
4. **Chrome 抓网络请求**：`mcp__Claude_in_Chrome__read_network_requests` 看实际发出的请求
5. **响应 schema 校验**：用 JSON Schema 或手动核对每个字段
6. **性能测试**：`time curl ...` 看响应时间；`ab -n 100 -c 10 ...` 看并发
7. **重放测试**：同一请求多次发送，验证幂等性

## 常见 Bug 模式

- 文档说必填字段，实际可选（或反之）
- 文档 camelCase，实际 snake_case
- 文档返回数组，实际返回对象（或反之）
- 文档状态码 200，实际返回 200 但 body.code = 500
- 错误码与文档不一致（文档 401，实际 403）
- 错误响应结构不一致（成功返回 `{data}`，失败返回 `{error}` 没有 wrapper）
- 空字段表示混乱（null / "" / undefined / 不返回 字段）
- 时间格式混乱（毫秒时间戳 / 秒时间戳 / ISO 字符串 / 自定义格式 混用）
- 分页参数文档说 page/size，实际是 offset/limit
- 排序参数文档说 `sort=field,desc`，实际是 `sortBy=field&order=desc`
- ID 字段类型不一致（请求是 string，响应是 number）
- 越权返回 404 假装资源不存在（应返回 403）
- 鉴权失败返回 500（应返回 401）
- 敏感字段全文返回（应脱敏：138****1234）
- 大对象未分页，响应体超过 1MB
- 并发创建出现重复记录（缺幂等键）
- 跨域配置错误，OPTIONS 预检失败
- 接口响应 > 3s 无超时处理

## 通过判定

- 契约表 100% 一致（字段名/类型/必填/嵌套）
- 状态码全集（2xx + 至少 3 个 4xx + 至少 1 个 5xx）已覆盖
- 错误响应结构统一
- 时间/ID/分页/排序/枚举 等规范一致
- 关键接口 P95 响应时间 ≤ 业务要求阈值
- 敏感字段已脱敏或不返回
- 关键非幂等接口有幂等键设计
