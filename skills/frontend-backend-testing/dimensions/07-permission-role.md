# 维度 07 · 权限与角色测试

> 检查不同角色看到的菜单、按钮、页面、数据是否正确，是否存在越权访问。

## Checklist

- 菜单可见性：每个角色应见/不应见的菜单
- 按钮可见性：新增/编辑/删除/导出/审批 等高权限操作
- 页面访问：直接访问 URL 是否被拦截
- 数据可见性：列表是否只返回当前用户/部门数据（行级权限）
- 字段可见性：敏感字段是否对低权限角色隐藏（列级权限）
- 操作权限：能否通过接口绕过 UI 执行越权操作
- 横向越权：A 用户操作 B 用户的资源
- 纵向越权：普通用户调管理员接口
- 委托/代办：是否可代他人操作
- 角色切换：切换后菜单/数据是否刷新
- 权限变更：实时生效还是次日生效
- 离职/封禁：账号失效是否立即生效

## 测试方法

1. **角色矩阵**：
   ```
   | 资源/操作    | 超管 | 管理员 | 普通员工 | 访客 |
   | 用户列表查看 | ✓    | ✓      | ✗        | ✗    |
   | 用户删除     | ✓    | ✗      | ✗        | ✗    |
   ```
2. UI 测试 + 接口测试"双层"：UI 隐藏不算安全，必须接口也拦截
3. 用 curl 带不同角色 Token 直接打接口，验证 401/403
4. 横向越权测试：A 用户的 Token 调 B 用户的资源 URL

## 常见 Bug 模式

- 前端隐藏菜单/按钮，接口不校验 → 直接 curl 绕过
- 路由不拦截，直接输 URL 可访问
- 列表用全表查询再前端过滤 → 数据已泄露
- 横向越权 GET /api/orders/123 任意改 ID
- 鉴权信息只看前端 cookie/role，不验后端
- 权限变更不实时（需重新登录才生效）
- 超管接口被普通用户碰到（权限注解漏加）
- 敏感字段（手机号、身份证、薪资）返回全部用户

## 通过判定

- 角色矩阵 100% 已测
- UI + 接口双层拦截
- 无横向越权漏洞
- 无纵向越权漏洞
- 敏感字段按角色脱敏
