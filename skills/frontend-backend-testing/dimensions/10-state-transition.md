# 维度 10 · 状态流转测试

> 检查订单、审批、任务、流程等业务状态是否能按照规则正确流转，是否存在非法跳转。

## Checklist

- 所有合法状态枚举（待提交/待审/已通过/已拒/已撤回/已完成…）
- 所有合法迁移路径（A→B、B→C…）
- 所有非法迁移必须被拒绝（已通过 → 待提交 ✗）
- 每个状态对应可见的操作按钮（已通过状态下不应有"撤回"按钮）
- 状态变更后相关字段同步（如订单已支付 → paid_at 字段）
- 状态变更的并发：A 审批通过同时 B 撤回，谁赢？
- 状态变更的副作用：通知发送、积分变更、库存扣减
- 状态展示一致：列表 / 详情 / 弹窗 显示一致
- 状态颜色 / 文案 与业务约定一致
- 终态不可逆（已完成 / 已删除）

## 测试方法

1. **状态迁移图**绘制（见 `methods/state-transition.md`）
2. 用例 = 每条合法迁移边 1 个 + 每条非法迁移 1 个
3. 接口层直接构造非法迁移请求，验证拒绝
4. 并发测试：两端同时操作

## 常见 Bug 模式

- UI 按钮限制非法迁移但接口未拦截
- 状态字段是字符串没有枚举校验，可写入任意值
- 状态变更副作用部分成功（订单状态更新了，库存没扣）
- 并发审批通过两次（无乐观锁）
- 终态被回退（"已完成"被改回"进行中"）
- 列表状态文案 vs 详情状态文案不一致
- 状态颜色乱（成功用红色、失败用绿色）

## 通过判定

- 状态迁移图完整覆盖（每条边都有用例）
- 非法迁移接口层拦截
- 状态副作用事务化
- 终态不可逆已校验
