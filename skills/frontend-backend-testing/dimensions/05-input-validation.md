# 维度 05 · 输入校验与边界值测试

> 检查必填项、格式限制、长度限制、最大值、最小值、特殊字符等是否正确校验。

## Checklist

- 必填项：空、空格、只填一项
- 长度边界：min-1 / min / min+1 / max-1 / max / max+1
- 数值边界：0 / 负数 / 极大值 / 极小值 / 小数 / 科学计数法
- 格式：邮箱 / 手机 / 身份证 / URL / IP / 日期 / 时间 / 正则
- 字符集：英文 / 中文 / 日文 / Emoji / 全角半角 / 控制字符 / 零宽字符
- 特殊字符：& < > " ' \ / 空格、Tab、换行、NULL
- 注入：SQL / XSS / 命令注入 / 模板注入 payload
- 大小写敏感
- 首尾空格：是否 trim
- 多语言输入法状态（候选词未确认）
- 复制粘贴：富文本/带样式内容
- 文件名特殊字符：路径分隔符、保留名（CON、PRN）

## 测试方法

1. **等价类划分** → 见 `methods/equivalence-partitioning.md`
2. **边界值分析** → 见 `methods/boundary-value.md`
3. 用脚本批量生成边界输入
4. 前端校验 + 接口校验"双层"测试：前端绕过（直接 curl）也必须校验

## 常见 Bug 模式

- 前端校验但接口没校验（绕过前端可写入脏数据）
- 接口校验但前端没校验（用户体验差）
- 必填校验放过纯空格输入
- 长度按字符数算但 DB 按字节算（中文超长）
- 邮箱正则过严或过松（test+tag@domain.com 被拒）
- 手机号只允许 11 位但开头校验缺失
- 数字接受 `1.0.0` / `--5` / `1e10`
- 浮点数精度（0.1 + 0.2 ≠ 0.3）
- Trim 缺失，重复账号"admin" vs "admin "
- 没过滤零宽字符，肉眼相同实际不同
- 校验提示用代码错误码不是人话

## 通过判定

- 每个输入字段必有边界值用例（按边界值分析法）
- 前后端"双校验"
- 校验失败有人类可读提示
- 边界字符集（中文/Emoji/控制字符）有明确处理策略
