# 维度 09 · 搜索 / 筛选 / 排序 / 分页测试

> 检查列表页面中搜索、筛选、排序、分页、清空条件等功能的正确性。

## Checklist

### 搜索
- 模糊匹配 vs 精确匹配 是否符合预期
- 空搜索：清空输入返回全部
- 关键字带特殊字符（空格 / % / _ / & / 引号）
- 搜索结果高亮命中关键字
- 搜索历史
- 防抖（输入时不每键都请求）

### 筛选
- 单选筛选 / 多选筛选 / 范围筛选
- 默认筛选值
- 清空筛选回到默认
- 多筛选条件组合（AND 逻辑）
- 筛选条件 URL 参数化（刷新保留）

### 排序
- 单列排序 / 多列排序
- 升序 / 降序 / 取消排序
- 排序图标视觉态
- null 值排序行为
- 中英文/数字混合排序

### 分页
- 每页数量（10 / 20 / 50 / 100）
- 跳页输入边界（0 / 负数 / 超过总页数 / 字母）
- 删除最后一页最后一条 → 当前页变空
- 总数为 0 / 1 / 整页数 / 非整页数
- 分页与筛选组合：换筛选条件应回到第 1 页
- 路由保留分页参数（刷新仍在原页）

## 测试方法

1. **正交组合**（搜索 × 筛选 × 排序 × 分页）→ 见 `methods/orthogonal-array.md`
2. 准备多组数据：0 条 / 1 条 / 整页 / 不满一页 / 超过 100 页
3. 接口层：直接 curl 测分页参数边界
4. Chrome 网络抓包看实际发出的参数

## 常见 Bug 模式

- 切筛选条件未重置页码（搜出来还在第 5 页，但只有 2 页）
- 删除最后一项后页码不回退，列表空
- 分页参数不在 URL，刷新丢失
- 总数计算错误（DISTINCT 漏写、JOIN 重复）
- 排序后分页错位（接口未带 stable order）
- 模糊搜索性能差（无索引，10w 数据 8 秒）
- 多筛选条件用 OR 不是 AND
- 搜索特殊字符（%）按 SQL 通配符匹配
- 翻页时上一页请求未取消，覆盖当前页结果

## 通过判定

- 搜索 / 筛选 / 排序 / 分页 四要素的正常 + 边界 + 组合用例齐备
- 0 / 1 / 整页 / 非整页 / 超大数据 五档数据量已测
- URL 参数化（刷新可恢复）
- 接口层稳定排序（避免分页错位）
