# 维度 16 · 回归测试

> 检查 Bug 修复后是否真正修复，相关功能是否受到影响，主流程是否仍然正常。

详细流程见 `modes/regression.md`，此处给出本维度独立测试时的要点。

## Checklist

- 原 Bug 已不可复现（用原复现步骤再走一遍）
- 同模块其他功能未受影响
- 共享组件 / 工具被改动时，所有使用方都过一遍
- 接口契约改动时，所有调用方都更新
- 数据迁移脚本是否幂等、可回滚
- 主流程冒烟 PASS
- 修复未引入新性能问题

## 测试方法

1. Bash `git diff` 看改动
2. Grep 找改动符号的引用方
3. 重跑原 Bug 复现路径
4. 跑回归测试套件 / 主流程冒烟

## 常见 Bug 模式

- "修了又坏"：修复方式只在某条路径生效，其他路径未覆盖
- 修复引入新 Bug（侧效应）
- 接口变更但前端未同步
- 数据迁移漏掉旧数据
- 修复掩盖症状不解根因

## 通过判定

- 原 Bug 复现路径再次走通 → 期望失败
- 影响面用例全 PASS
- lint / build / test 三连通过
