# 维度 01 · 原型交互测试

> 检查页面流程、按钮操作、弹窗、跳转、表单提交等交互是否符合原型设计。

## Checklist（要看什么）

- 所有可交互元素（按钮 / 链接 / 输入框 / 下拉 / 复选 / 单选 / 上传 / 拖拽）是否都有响应
- 跳转关系：从 A 页跳到 B 页的入口、出口、返回链路是否与原型一致
- 弹窗 / Toast / Modal：触发条件、确认/取消行为、关闭方式、背景遮罩
- 表单提交：提交触发条件、提交按钮 loading 态、防重复提交
- 二次确认：删除/解绑/支付等高风险操作是否有二次确认
- 操作可逆性：是否提供撤销、返回、重置入口
- 默认值：表单默认填充、勾选默认状态、列表默认排序是否符合原型
- 默认聚焦：进入页面/弹窗后焦点是否正确
- 键盘交互：Tab 顺序、Enter 提交、Esc 关闭弹窗
- 移动端：长按、滑动、下拉刷新、上拉加载是否符合原型
- 引导/空状态/加载态/错误态：原型有的状态是否都实现了

## 测试方法

1. **原型节点提取**：把原型按"页面 → 区块 → 元素 → 状态"拆解，列出所有交互节点
2. **跳转关系图**：画出页面间跳转的有向图，每条边对应一个用例
3. **状态枚举矩阵**：每个元素列出 6 个状态（默认/hover/active/disabled/error/loading），逐一对照
4. **实测工具**：
   - `mcp__Claude_in_Chrome__navigate` 打开页面
   - `mcp__Claude_in_Chrome__get_page_text` 看渲染结构
   - `mcp__Claude_in_Chrome__find` + 点击模拟交互
   - 对比原型截图（如有 .pen 用 `mcp__pencil__get_screenshot`）

## 常见 Bug 模式

- 按钮多次点击触发多次提交（缺防抖/loading 锁）
- 弹窗关闭后页面状态未重置
- 跳转后返回，原页面状态丢失
- 表单提交失败未恢复 loading 态
- 删除操作缺二次确认
- Tab 顺序混乱
- Enter 键提交错误表单
- 移动端没有处理软键盘弹起遮挡输入框
- 异步加载未完成时按钮可点
- 模态弹窗下层页面可滚动

## 通过判定

- 原型上所有可交互元素 100% 有对应用例
- 跳转矩阵无遗漏边
- 6 状态矩阵每个组件至少覆盖默认/loading/error/empty 四态
- 高风险操作均有二次确认
- 所有"非幂等"操作有防重复提交机制
