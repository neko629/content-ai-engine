# 维度 17 · 用户体验测试

> 检查操作是否清晰、提示是否友好、流程是否顺畅、错误提示是否容易理解。

## Checklist

- 提示文案：人话不是代码错误号
- 操作反馈：成功 / 失败 / 处理中 都有反馈
- 操作路径长度（关键操作 ≤ 3 步）
- 重要操作有结果反馈（弹窗 / Toast / Banner）
- 错误恢复路径明确（"重试"按钮 / 返回上一步）
- 表单填写：错误标注在出错字段附近
- 自动保存 / 草稿
- 移动端：按钮够大（≥ 44×44）、关键操作不在边缘
- 文案一致：同一概念用同一词
- 国际化（如有）：所有文案可翻译，没有 hardcode
- 帮助文档 / FAQ / 客服入口
- 加载占位避免白屏闪烁

## 测试方法

1. 假装第一次用：从入口走到完成全流程，记录困惑点
2. 不同角色走主流程
3. 极端用户场景：老年人、色盲、低带宽

## 常见 Bug 模式

- 错误提示是 "Error: code 500" 不是人话
- 操作完无反馈（不知成不成）
- 跳转后没回到原位置
- 关键按钮 disabled 但没说为啥
- 长流程无草稿，刷新全没
- 同一概念用了不同词（订单/单据/工单 混用）
- 文案硬编码无法 i18n
- 弱网下首屏空白 5 秒

## 通过判定

- 主流程"陌生人能走通"
- 错误提示均为人话且含恢复路径
- 关键反馈、空状态、加载态齐备
- 文案一致性、可翻译性符合要求
