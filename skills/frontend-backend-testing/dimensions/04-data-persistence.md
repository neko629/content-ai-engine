# 维度 04 · 数据传输与落库测试

> 检查前端提交的数据是否能正确传到后端，后端保存后再次查询是否一致。

## Checklist

- 前端提交字段 → 网络请求 body → 数据库存储 → 再次查询返回 → 前端展示，全链路字段值一致
- 字段类型不丢精度（数字、时间、长 ID、Decimal）
- 中文 / Emoji / 特殊字符（&、<、>、引号、换行、 ）落库无损
- 长文本（10KB / 100KB）落库不被截断
- 时区：前端时区、服务端时区、数据库时区一致
- 时间字段：created_at / updated_at 是否自动维护
- 软删除字段：deleted_at 是否正确设置
- 关联表：主表插入后从表是否同步
- 缓存一致性：Redis / 本地缓存与 DB 是否同步
- 事务：失败时是否回滚干净
- 并发写：是否使用乐观锁/悲观锁

## 测试方法

1. 前端表单 → 抓 Chrome 网络请求 → 看 DB 实际存储 → 重新查询接口看返回值
2. Bash 直连 DB：`mysql -e "SELECT * FROM users WHERE id=..."` / `psql` / `redis-cli`
3. 大文本/特殊字符测试：用脚本生成边界数据提交
4. 时区测试：浏览器切换时区，验证存储与展示

## 常见 Bug 模式

- 前端 Number 精度丢失（JS 长整型 > 2^53）
- 字符串截断（VARCHAR(255) 但前端无限制）
- Emoji 落库变 ??? （DB 字符集非 utf8mb4）
- 时区错乱（存的 UTC，查的本地时间，展示又错一次）
- 软删除未过滤，列表显示已删除项
- 关联表外键未级联，主表删除从表残留
- 缓存与 DB 不一致（更新 DB 没刷缓存）
- 事务失败部分落库

## 通过判定

- 全链路字段值一致
- 边界字符（长字符串/Emoji/特殊字符）落库无损
- 时区在前端/接口/DB 链路统一
- 软删除/缓存一致性符合业务预期
