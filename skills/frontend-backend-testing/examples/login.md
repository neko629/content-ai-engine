## 测试输入分析

**原型节点提取：**
- 元素：账号输入、密码输入、记住密码、登录按钮、忘记密码链接、第三方登录入口
- 跳转：登录成功 → /home；忘记密码 → /forgot；第三方 → OAuth
- 状态：默认 / 输入中 / 校验失败 / 登录中 / 登录失败

**接口契约（POST /api/v1/auth/login）：**
| 字段 | 类型 | 必填 | 说明 |
| username | string | ✓ | 4–32 字符 |
| password | string | ✓ | 6–32 字符 |
| remember | boolean | ✗ | 默认 false |

响应：
- 200：`{ token, refresh_token, user: { id, name } }`
- 400：`{ code, message }` 字段校验失败
- 401：账号或密码错误
- 429：登录失败次数过多

## 问题清单（节选）

[BUG-001] 严重 · 维度 14
- 标题：[登录] 账号输入框存在反射型 XSS
- 复现：账号输 `<script>alert(1)</script>` 后点登录
- 实际：错误提示直接 innerHTML 用户输入，弹出 alert
- 建议：错误提示统一 textContent，前后端双重转义，引入 CSP

[BUG-002] 严重 · 维度 08
- 标题：[登录] 退出登录后服务端 Session 仍有效
- 复现：登录 → 退出 → 用旧 Token 直接打接口
- 实际：仍能访问，服务端未注销
- 建议：退出接口要清服务端 Session，Token 加入黑名单
