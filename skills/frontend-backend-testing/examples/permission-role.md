# 示例 · 权限角色（维度 07）

## 用户输入
> "我们有 4 个角色，测一下权限隔离"

## 角色定义
- 超管：全部权限
- 部门管理员：本部门所有权限
- 普通员工：自己创建的资源 + 查看本部门公开资源
- 访客：仅查看公开数据

## 权限矩阵

| 资源\角色 | 超管 | 部门管理员 | 普通员工 | 访客 |
|---|---|---|---|---|
| 用户列表-查看 | 全部 | 本部门 | ✗ | ✗ |
| 用户列表-新增 | ✓ | 本部门 | ✗ | ✗ |
| 用户列表-编辑 | 任意 | 本部门 | ✗ | ✗ |
| 用户列表-删除 | ✓ | ✗ | ✗ | ✗ |
| 订单列表-查看 | 全部 | 本部门 | 自己 | ✗ |
| 订单-编辑 | 任意 | 本部门 | 自己 | ✗ |
| 系统配置 | ✓ | ✗ | ✗ | ✗ |

每格 = 1 个用例（UI + 接口双层）

## 测试用例（节选）

| # | 角色 | 资源/操作 | UI 测试 | 接口测试 |
|---|---|---|---|---|
| 1 | 普通员工 | 用户列表-菜单 | 菜单不可见 | curl 调 GET /api/users 应 403 |
| 2 | 普通员工 | 用户编辑-URL 直访 | 跳无权限页 | curl PUT /api/users/x 应 403 |
| 3 | 普通员工 | 横向越权-改 ID | - | GET /api/orders/{他人ID} 应 403/404 |
| 4 | 普通员工 | 自己的订单 | 可见可编辑 | PUT /api/orders/{自己ID} 应 200 |
| 5 | 部门管理员 | 跨部门订单 | 不可见 | GET 返回不含跨部门 |
| 6 | 部门管理员 | 直接查跨部门 ID | - | GET /api/orders/{跨部门} 应 403 |
| 7 | 访客 | 全部功能 | 只能看公开 | 任意写接口应 403 |
| 8 | 任一角色 | 切换角色 | 菜单/数据刷新 | Token 重新签发 |
| 9 | 任一角色 | 离职后 | 应被踢出 | 接口应 401 |
| 10 | 任一角色 | 敏感字段 | 普通员工看到的手机号脱敏 | 接口返回已脱敏 |

## 工具实测

```bash
# 用三个角色 Token 分别打同一接口对比
for token in $ADMIN_TOKEN $MANAGER_TOKEN $USER_TOKEN; do
  echo "Token: $token"
  curl -s -o /dev/null -w "%{http_code}\n" \
    -H "Authorization: Bearer $token" \
    https://api.example.com/v1/users
done

# 横向越权
curl -H "Authorization: Bearer $USER_A_TOKEN" \
  https://api.example.com/v1/orders/{USER_B_ORDER_ID}
# 期望：403 或 404
```

## 常见 Bug
- 前端隐藏菜单，接口未拦截
- 列表用全表查询前端过滤（数据已泄露）
- 横向越权改 ID
- 敏感字段对低权限角色返回明文
- 权限变更不实时
- 委托 / 代办权限混乱

## 通过判定
- 矩阵 100% 已测
- UI + 接口 双层拦截
- 横向 / 纵向越权用例无遗漏
- 敏感字段已脱敏
