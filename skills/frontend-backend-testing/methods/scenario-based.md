# 测试设计方法 · 场景法（端到端）

## 概念

把用户从入口到目标的完整路径作为一个场景，端到端测试。每个场景至少覆盖：

- Happy Path（理想路径）
- Alternate Path（替代路径，达到同一目标）
- Exception Path（异常路径）

## 步骤

1. 找用户角色和目标
2. 画用户旅程：步骤 1 → 步骤 2 → … → 完成
3. 每步识别可能的"分叉"
4. 主路径 + 至少 1 个替代路径 + 至少 1 个异常路径

## 示例：电商下单场景

**Happy Path**：
浏览商品 → 加入购物车 → 结算 → 选地址 → 选支付方式 → 支付 → 订单成功

**Alternate Path 1**：直接"立即购买"跳过购物车

**Alternate Path 2**：使用优惠券

**Exception Path 1**：支付中关页面

**Exception Path 2**：库存不足

**Exception Path 3**：地址校验失败

每条路径对应 1 个 E2E 测试用例。

## 适用场景

- 端到端测试（E2E）
- 验收测试
- 主流程冒烟
