# 测试设计方法 · 状态迁移

## 概念

业务有状态时（订单、审批、任务），画状态图，每条合法迁移 1 个用例，每个非法迁移至少 1 个用例。

## 步骤

1. 枚举所有状态
2. 枚举所有触发事件
3. 画状态图（节点 = 状态，边 = 事件）
4. 列出**合法迁移**和**非法迁移**
5. 每条边 = 1 个用例

## 示例：订单状态机

```
[待支付] --支付成功--> [已支付]
[待支付] --超时/取消--> [已取消]
[已支付] --发货--> [已发货]
[已支付] --退款--> [已退款]
[已发货] --签收--> [已完成]
[已发货] --拒签--> [退货中]
[已完成] --申请售后--> [售后中]
```

合法迁移用例（每条 1 个）：

| 起始状态 | 事件 | 目标状态 |
|---|---|---|
| 待支付 | 支付成功 | 已支付 |
| 待支付 | 取消 | 已取消 |
| 已支付 | 发货 | 已发货 |
| …… | …… | …… |

非法迁移用例（至少覆盖典型）：

| 起始状态 | 事件 | 预期 |
|---|---|---|
| 已完成 | 退款 | 拒绝（必须经过售后） |
| 已取消 | 发货 | 拒绝（不可逆终态） |
| 已发货 | 重新支付 | 拒绝 |

## 注意点

- 终态不可再迁出（已完成、已取消）
- 并发触发：A 端发货同时 B 端取消，看锁
- 状态字段是否枚举校验，可写脏值
