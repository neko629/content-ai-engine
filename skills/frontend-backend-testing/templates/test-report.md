# 测试报告标准模板

```
# [模块/页面/功能] 测试报告

## 0. 质量门禁状态
- 维度覆盖：[X/21] 已覆盖，未覆盖原因：……
- P0 路径覆盖：[X/X] 100% / 不达标说明
- 已实测项 / 未实测项：[X/Y]
- 结论：✅ PASS / ⚠️ 有条件 PASS / ❌ FAIL

## 1. 测试范围
- 模式：全量速测 / 分项深测 / 增量回归 / 测试编排
- 覆盖范围：[页面/模块/接口列表]
- 范围外：[显式排除]

## 2. 测试输入分析
（结构化提取结果）
- 原型：交互节点 N 个、跳转关系 M 条
- UI Token：色值 N、字号 N、间距 N
- 接口：N 个、覆盖状态码 [200, 400, 401, 403, 500]
- 业务规则：N 条
- 代码：路由 N、组件 N、接口调用关系图

## 3. 测试点（按维度组织）
### 维度 01 - 原型交互
- ……
### 维度 02 - UI 布局
- ……
（17 业务/质量维度 + 4 代码工程维度，按需展开；不适用维度需注明）

## 4. 测试用例
（表格形式，见 templates/test-case.md）

## 5. 测试矩阵（如适用）
（多变量场景见 templates/test-matrix.md）

## 6. 问题清单
（每条按 templates/bug-report.md 结构）

## 7. 严重程度统计
- 严重 N 条 / 一般 N 条 / 轻微 N 条
- TOP 问题：……

## 8. 复现步骤
（每条问题附最小复现路径）

## 9. 修改建议
（按问题给出修复方向）

## 10. 回归建议
- 修复后需重测：……
- 受影响范围：……
- 建议补充自动化：……

## 11. 工具实测记录
（命令 + 输出摘录，证明已实测）

## 12. 下一步建议
- 建议进入「分项深测」的维度：……
- 建议补的材料：……
```
